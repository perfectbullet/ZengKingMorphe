# API 认证迁移总结

## 变更概述

本次变更将项目的认证方式从 JWT Token 迁移到 API Key 认证，并移除了所有第三方 JWT 依赖。

## 修改的文件

### 1. 认证中间件 (`app/api/middleware/auth.py`)

**删除的功能：**
- `create_access_token()` - JWT token 生成函数
- `verify_token()` - JWT token 验证函数  
- `get_current_user()` - 从 JWT token 获取用户信息
- `get_current_user_optional()` - 可选的 JWT/API Key 双模式认证
- `bearer_scheme` - HTTP Bearer 认证方案

**保留/更新的功能：**
- `verify_api_key()` - 更新为验证 API key 是否在配置的列表中
- `get_api_key()` - 新增，可选的 API key 验证（用于不强制认证的端点）
- `api_key_header` - API Key 头部定义

**关键变更：**
```python
# 之前：支持 JWT 和 API Key 双模式
async def get_current_user_optional(
    credentials: Optional[HTTPAuthorizationCredentials] = Security(bearer_scheme),
    api_key: Optional[str] = Security(api_key_header)
) -> Optional[dict]:
    # ... 复杂的双模式验证逻辑

# 现在：仅支持 API Key
async def verify_api_key(api_key: Optional[str] = Security(api_key_header)) -> str:
    if not api_key:
        raise HTTPException(status_code=401, detail="API key missing")
    if api_key not in settings.api_keys:
        raise HTTPException(status_code=401, detail="Invalid API key")
    return api_key
```

### 2. 配置文件 (`app/core/config.py`)

**删除的配置：**
- `jwt_secret_key` - JWT 密钥
- `jwt_algorithm` - JWT 算法（HS256）
- `jwt_expiration_minutes` - JWT 过期时间

**新增的配置：**
- `api_keys: List[str]` - API Key 列表

**配置变更：**
```python
# 之前
jwt_secret_key: str = Field(..., description="JWT secret key")
jwt_algorithm: str = Field(default="HS256")
jwt_expiration_minutes: int = Field(default=60, ge=1)

# 现在
api_keys: List[str] = Field(
    default=[],
    description="List of valid API keys for authentication"
)
```

### 3. 环境变量配置 (`.env.example`)

**删除的配置：**
```bash
JWT_SECRET_KEY=your-secret-key-change-this-in-production
JWT_ALGORITHM=HS256
JWT_EXPIRATION_MINUTES=60
```

**新增的配置：**
```bash
# API Key Configuration
# Comma-separated list of valid API keys for authentication
API_KEYS=your-api-key-1,your-api-key-2
```

### 4. API 端点更新

所有端点的认证参数从 `current_user: dict = Depends(get_current_user_optional)` 
更改为 `api_key: str = Depends(get_api_key)`

**更新的文件：**
- `app/api/endpoints/chat.py` (2 个端点)
- `app/api/endpoints/session.py` (2 个端点)
- `app/api/endpoints/employee.py` (5 个端点)
- `app/api/endpoints/knowledge_base.py` (4 个端点)
- `app/api/endpoints/conversation.py` (2 个端点)
- `app/api/endpoints/webhook.py` (3 个端点，更新返回类型)

**示例变更：**
```python
# 之前
@router.post("/message")
async def chat_message(
    request: ChatRequest,
    current_user: dict = Depends(get_current_user_optional)
):
    ...

# 现在
@router.post("/message")
async def chat_message(
    request: ChatRequest,
    api_key: str = Depends(get_api_key)
):
    ...
```

### 5. 依赖项 (`requirements.txt`)

**删除的依赖：**
- `PyJWT==2.8.0`
- `python-jose[cryptography]`
- `passlib[bcrypt]==1.7.4`

这些 JWT 相关的库已不再需要。

### 6. 测试文件 (`tests/test_api.py`)

**新增的测试：**
- `test_api_key_authentication()` - 测试 API Key 认证

**更新的测试：**
- `test_chat_message_validation()` - 添加 API Key 缺失的测试用例

```python
# 新增测试
@pytest.mark.asyncio
```

## 优势

1. **简化认证流程**
   - 移除了复杂的 JWT token 生成和验证逻辑
   - 不需要管理 token 过期时间
   - 减少了代码复杂度

2. **减少依赖**
   - 移除了 3 个第三方库（PyJWT, python-jose, passlib）
   - 降低了安全风险和维护成本

3. **更直接的认证**
   - API Key 直接存储在环境变量中
   - 无需数据库查询或复杂计算
   - 认证速度更快

4. **灵活的密钥管理**
   - 支持多个 API Key
   - 可以为不同客户端分配不同的 key
   - 易于撤销和更新

## 迁移步骤

如果您正在使用旧版本，请按以下步骤迁移：

1. **更新代码库**
   ```bash
   git pull origin main
   ```

2. **安装更新的依赖**
   ```bash
   cd ai-service
   pip install -r requirements.txt
   ```

3. **配置 API Keys**
   
   在 `.env` 文件中添加：
   ```bash
   API_KEYS='["your-api-key-1","your-api-key-2"]'
   ```
   
   生成安全的 API Key：
   ```python
   import secrets
   api_key = f"sk_{secrets.token_urlsafe(32)}"
   ```

4. **更新客户端代码**
   
   将所有使用 JWT 的地方改为使用 API Key：
   ```python
   # 之前
   headers = {"Authorization": f"Bearer {jwt_token}"}
   
   # 现在
   headers = {"X-API-Key": api_key}
   ```

5. **重启服务**
   ```bash
   docker-compose restart ai-service
   ```

## 注意事项

1. **向后兼容性**
   - 此变更不向后兼容
   - 所有现有的 JWT tokens 将失效
   - 客户端需要更新为使用 API Key

2. **安全建议**
   - 使用 HTTPS 传输
   - 定期轮换 API Keys
   - 不要在代码中硬编码 API Keys
   - 为不同环境使用不同的 keys

3. **API Key 管理**
   - 当前 API Keys 存储在配置文件中
   - 如需更高级的管理（如过期时间、权限级别），可考虑存储在数据库中
