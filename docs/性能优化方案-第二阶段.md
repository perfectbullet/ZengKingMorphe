### 🚀 方案2: 并行化FAQ和知识检索 (待实施)

**问题**: 当前FAQ匹配和知识检索串行执行,总耗时 = 1086ms + 84ms = 1170ms

**方案**: 同时启动两个检索任务,取最快的那个

#### 实现步骤

**步骤1**: 在 [conversation_service.py](../ai-service/app/services/conversation_service.py) 中添加并行检索节点

```python
async def parallel_retrieval(self, state: ConversationState):
    """
    并行执行FAQ匹配和知识检索。
    FAQ匹配成功则跳过知识检索,否则使用知识检索结果。
    """
    import asyncio

    # 同时启动FAQ和知识检索
    faq_task = asyncio.create_task(self.match_faq(state.copy()))
    kb_task = asyncio.create_task(self.knowledge_retrieval(state.copy()))

    # 等待FAQ完成
    await faq_task

    # 如果FAQ匹配成功,取消知识检索任务
    if state.get("faq_matched"):
        kb_task.cancel()
        logger.info("FAQ matched, skipping knowledge retrieval")
        return state

    # 否则等待知识检索完成
    await kb_task
    return state
```

**步骤2**: 修改LangGraph图结构

```python
# 修改前的串行流程
graph.add_edge("match_faq", "intent_recognition")

```

#### 预期效果
- **串行执行**: 1086ms + 84ms = 1170ms
- **并行执行**: **max(1086ms, 84ms) = 1086ms**
- **改善幅度**: 7% (在FAQ未匹配时)

**注意**: 由于FAQ匹配(1086ms)远慢于知识检索(84ms),并行的收益有限。**更有效的方案是优化FAQ匹配速度本身**。

### 🎯 方案3: FAQ匹配优化 (推荐)

**问题**: FAQ匹配耗时1086ms,其中90%+是embedding请求时间

#### 3.1 批量Embedding FAQ问题

**预计算策略**: 在员工配置加载时,批量生成所有FAQ问题的embedding并缓存

**实现位置**: [app/services/employee_service.py](../ai-service/app/api/endpoints/employee.py)

```python
async def preload_faq_embeddings(employee_id: str, faq_list: List[dict]):
    """
    预计算FAQ问题的embedding并缓存
    """
    from app.utils.embeddings import get_embedding

    embedder = get_embedding()
    questions = [faq['question'] for faq in faq_list]

    # 批量生成embedding (一次性调用API)
    embeddings = embedder.embed_documents(questions)

    # 存储到缓存
    for faq, emb in zip(faq_list, embeddings):
        embedding_cache.set(faq['question'], embedder.model, emb)

    logger.info(f"Preloaded {len(embeddings)} FAQ embeddings", employee_id=employee_id)
```

**调用时机**: 在 [load_employee_config](../ai-service/app/services/conversation_service.py#L272) 时触发

#### 3.2 FAQ向量索引优化

**当前问题**: ChromaDB每次都重新计算相似度

**优化方案**:
1. 使用更小的embedding模型 (如 `bge-small-zh-v1.5`)
2. 减少返回的文档数量 (从6降到3)
3. 使用HNSW索引加速向量搜索

#### 预期效果
- **首次FAQ匹配**: 100ms+ (需要计算embedding)
- **后续FAQ匹配**: **<20ms** (使用缓存的embedding)
- **改善幅度**: **98%** (针对FAQ匹配)
