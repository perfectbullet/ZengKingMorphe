## ✅ 已完成的优化

### 1. Ollama保活服务 ⭐⭐⭐
**文件**: [app/services/ollama_keepalive.py](../ai-service/app/services/ollama_keepalive.py)

- 每3分钟自动发送健康检查请求
- 防止模型在空闲时被卸载
- 支持配置 `OLLAMA_KEEP_ALIVE_INTERVAL`

**预期效果**: 二次请求TTFB从4000ms降至<1000ms (-75%)

### 2. Embedding缓存服务 ⭐⭐⭐
**文件**: [app/services/embedding_cache.py](../ai-service/app/services/embedding_cache.py)

- LRU缓存策略,自动淘汰旧数据
- 线程安全,支持并发访问
- 统计监控,跟踪命中率

**集成位置**:
- [app/utils/embeddings.py:47](../ai-service/app/utils/embeddings.py#L47) - 检查缓存
- [app/utils/embeddings.py:73](../ai-service/app/utils/embeddings.py#L73) - 保存缓存

**预期效果**:
- 首次查询: 1086ms
- 重复查询: <10ms (-99%)

### 3. keep_alive参数 ⭐⭐
**修改文件**:
- [app/utils/embeddings.py:53](../ai-service/app/utils/embeddings.py#L53) - embedding请求
- [app/services/conversation_service.py:92](../ai-service/app/services/conversation_service.py#L92) - LLM请求

每次Ollama API调用添加 `keep_alive=-1`,防止模型被卸载

**预期效果**: 延长模型在内存中的保持时间

## 🚀 待实施的优化

### 高优先级 (推荐立即实施)

#### 1. 切换到更快的LLM ⭐⭐⭐⭐⭐
**当前**: Ollama qwen2.5:7b (~18 tok/s)
**推荐**: SiliconFlow DeepSeek-V3 (~50 tok/s)

**配置**:
```bash
# .env or .env-win
USE_OLLAMA=false
OPENAI_API_BASE=https://api.siliconflow.cn/v1
OPENAI_MODEL=deepseek-ai/DeepSeek-V3
```

**预期效果**: LLM生成从3722ms降至1500ms (-60%)

#### 2. FAQ embedding预计算 ⭐⭐⭐⭐
**问题**: 每次FAQ匹配都要调用embedding API

**方案**: 在员工配置加载时,批量生成所有FAQ问题的embedding

**实现**:
```python
# 在 load_employee_config 中调用
async def preload_faq_embeddings(employee_id: str, faq_list: List[dict]):
    embedder = get_embedding()
    questions = [faq['question'] for faq in faq_list]
    embeddings = embedder.embed_documents(questions)

    for faq, emb in zip(faq_list, embeddings):
        embedding_cache.set(faq['question'], embedder.model, emb)
```

**预期效果**: FAQ匹配从1086ms降至200ms (-82%)

### 中优先级

#### 3. 并行化FAQ和知识检索 ⭐⭐⭐
**当前**: 串行执行 (1086ms + 84ms = 1170ms)
**优化**: 并行执行 (max(1086ms, 84ms) = 1086ms)

**预期效果**: 总检索时间减少7%

#### 4. 优化ElasticSearch查询 ⭐⭐
**问题**: 返回1156条命中但只用10条

**方案**:
- 减少返回数量 (10→5)
- 只返回需要的字段
- 优化查询条件

**预期效果**: ES查询减少20-30%
