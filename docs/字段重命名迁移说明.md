# 字段重命名迁移说明

## 修改概述

将外部 API 模型的 `id` 字段重命名为业务语义字段并转换为 `str` 类型：

1. **ExternalFAQItem.id** → **faq_id: str**
2. **ExternalRAGDataset.id** → **kb_id: str**  
3. **ExternalEmployeeInfo.id** → **employee_id: str**
4. **ExternalRuleConfig.id** → **rule_config_id: str**

所有字段都添加了 `alias="id"` 以保持与 Java 平台 API 的兼容性（Pydantic 会自动处理字段名映射）。

## 修改的文件

### 1. [schemas.py](ai-service/app/models/schemas.py)
修改了 4 个外部 API 模型类的字段定义：
- `ExternalFAQItem.faq_id: str` (原 `id: int`)
- `ExternalRAGDataset.kb_id: str` (原 `id: int`)
- `ExternalEmployeeInfo.employee_id: str` (原 `id: int`)
- `ExternalRuleConfig.rule_config_id: str` (原 `id: int`)

### 2. [database.py](ai-service/app/models/database.py)
更新了数据库模型的外部 ID 字段类型：
- `FAQModel.external_faq_id: str` (原 `int`)
- `DigitalEmployeeConfigModel.external_employee_id: str` (原 `int`)

### 3. [session.py](ai-service/app/api/endpoints/session.py)
修改了字段访问方式：
```python
# 旧代码
employee_id = str(employee_info["id"])
external_employee_id = employee_info["id"]

# 新代码  
employee_id = employee_info["employee_id"]  # 直接使用，已经是 str
external_employee_id = employee_info["employee_id"]
```

### 4. [task_processor.py](ai-service/app/services/task_processor.py)
修改了 FAQ 向量化任务中的字段访问：
```python
# 旧代码
external_faq_id = faq_data["id"]

# 新代码
external_faq_id = faq_data["faq_id"]  # 使用新字段名
```

## API 兼容性

由于使用了 Pydantic 的 `alias` 机制，Java 平台的 API 返回数据格式无需修改：

```json
{
  "employee": {
    "id": 123,  // ← Java API 继续使用 "id" 字段
    "name": "测试员工"
  },
  "setting": {
    "knowledge": {
      "faqs": [
        {
          "id": 456,  // ← Java API 继续使用 "id" 字段
          "questionName": "测试问题"
        }
      ]
    }
  }
}
```

Pydantic 会自动将 JSON 中的 `"id"` 映射到 Python 代码中的 `employee_id`、`faq_id` 等字段。

## 代码访问方式

在 Python 代码中访问字段时，**必须使用新字段名**：

```python
# ✅ 正确 - 使用新字段名
employee_id = employee_info.employee_id
faq_id = faq_data.faq_id
kb_id = dataset.kb_id

# ❌ 错误 - 旧字段名不存在
employee_id = employee_info.id  # AttributeError!
```

通过字典访问时，可以使用 `alias` 名称或新字段名（推荐使用新字段名）：

```python
# ✅ 推荐 - 使用新字段名
employee_id = employee_info["employee_id"]

# ⚠️  也可以但不推荐 - 使用 alias
employee_id = employee_info["id"]  # Pydantic 会自动映射
```

## 注意事项

1. **字段类型变更**：所有 `id` 字段从 `int` 改为 `str`，确保不要进行整数运算
2. **字符串拼接**：`f"faq_{employee_id}_{external_faq_id}"` 在 `str` 类型下更自然
3. **数据库查询**：MongoDB/ES 查询时确保使用字符串值匹配
4. **无向后兼容**：此修改不保留向后兼容性，必须清理旧数据
