# 数字员工 AI 服务部署指南

## 一、环境准备

### 1.1 系统要求
- Ubuntu 20.04+ / CentOS 8+ / macOS 12+
- Docker 20.10+
- Docker Compose 2.0+
- 至少 4GB 可用内存
- 至少 10GB 可用磁盘空间

### 1.2 必需的 API 密钥
- **OpenAI API Key**（必需）：用于 LLM 和 Embedding
- **Tavily API Key**（可选）：用于联网检索
- **JWT Secret Key**（必需）：用于鉴权

## 二、快速部署

### 2.1 克隆项目
```bash
git clone https://github.com/perfectbullet/ZengKingMorphe.git
cd ZengKingMorphe
```

### 2.2 配置环境变量
```bash
cd ai-service
cp .env.example .env
```

编辑 `.env` 文件，填入必要的配置：
```bash
# 必需配置
OPENAI_API_KEY=sk-your-openai-api-key
JWT_SECRET_KEY=your-jwt-secret-key-min-32-chars

# 可选配置
TAVILY_API_KEY=tvly-your-tavily-api-key  # 联网检索
JAVA_API_BASE_URL=http://java-platform:8080  # Java 平台地址
```

### 2.3 启动服务
```bash
# 返回项目根目录
cd ..

# 启动所有服务
docker-compose up -d

# 查看服务状态
docker-compose ps

# 查看日志
docker-compose logs -f ai-service
```

### 2.4 验证部署
访问以下 URL 验证服务是否正常：

- **API 文档**: http://localhost:8000/docs
- **健康检查**: http://localhost:8000/health
- **根路径**: http://localhost:8000/

预期响应：
```json
{
  "service": "Digital Employee AI Service",
  "version": "1.0.0",
  "status": "running"
}
```

## 三、服务组件

### 3.1 AI Service
- **端口**: 8000
- **功能**: AI 对话引擎、知识库管理
- **依赖**: MongoDB, Chroma, ElasticSearch

### 3.2 MongoDB
- **端口**: 27017
- **功能**: 对话记录、会话、配置存储
- **数据持久化**: `mongodb-data` volume

### 3.3 Chroma
- **端口**: 8001
- **功能**: 向量数据库
- **数据持久化**: `chroma-data` volume

### 3.4 ElasticSearch
- **端口**: 9200, 9300
- **功能**: 全文检索
- **数据持久化**: `es-data` volume

```bash
    "personality": {

    "capabilities": {

```

### 4.2 创建知识库

```bash
curl -X POST http://localhost:8000/api/knowledge-base/create \
  -F "name=产品知识库" \
  -F "description=产品相关的知识库" \
  -F "category=产品"
```

```bash

  -F "kb_id=kb_001" \
  -F "files=@/path/to/document1.pdf" \
  -F "files=@/path/to/document2.docx" \
  -F "category=产品文档"
```

### 4.4 发起对话


```bash

# 备份 Chroma
docker cp digital-employee-ai:/app/chroma_db ./chroma-backup

# 备份 ElasticSearch
docker exec digital-employee-elasticsearch curl -X PUT "localhost:9200/_snapshot/backup/snapshot_1?wait_for_completion=true"
```

## 六、故障排查

### 6.1 服务无法启动
**问题**: docker-compose up 失败
**解决方案**:
1. 检查端口是否被占用：`lsof -i :8000,27017,9200,8001`
2. 检查 Docker 服务：`systemctl status docker`
3. 查看详细错误：`docker-compose logs`

### 6.2 数据库连接失败
**问题**: AI Service 无法连接数据库
**解决方案**:
1. 确认数据库容器运行：`docker-compose ps`
2. 检查网络连接：`docker network ls`
3. 查看数据库日志：`docker-compose logs mongodb`

### 6.3 API 返回 500 错误
**问题**: 请求失败，返回内部错误
**解决方案**:
1. 查看应用日志：`docker-compose logs -f ai-service`
2. 检查 OpenAI API Key 是否有效
3. 确认所有依赖服务正常运行

### 6.4 内存不足
**问题**: ElasticSearch 启动失败
**解决方案**:
1. 增加 Docker 内存限制
2. 调整 ES_JAVA_OPTS：在 docker-compose.yml 中设置 `-Xms512m -Xmx512m`

## 七、性能优化

### 7.1 调整并发数
编辑 `ai-service/.env`:
```bash
API_WORKERS=8  # 增加 worker 数量
MAX_CONCURRENT_SESSIONS=200  # 增加并发会话限制
```

### 7.2 调整向量检索参数
编辑 `ai-service/.env`:
```bash
CHUNK_SIZE=512  # 分块大小
CHUNK_OVERLAP=50  # 重叠大小
RELEVANCE_THRESHOLD=0.6  # 相关性阈值
```

### 7.3 使用缓存
- MongoDB 查询缓存（内置）
- Chroma 索引缓存（内置）
- Redis 缓存（可选，需额外配置）

## 八、安全建议

### 8.1 生产环境配置
1. 更换强 JWT Secret Key（至少 32 字符）
2. 启用 HTTPS（使用 nginx 反向代理）
3. 配置防火墙规则
4. 定期更新 Docker 镜像
5. 定期备份数据

### 8.2 API 安全
1. 启用 API Key 认证
2. 配置 IP 白名单
3. 设置请求限流
4. 启用日志审计

### 8.3 数据安全
1. 加密敏感数据
2. 定期备份
3. 访问控制
4. 定期安全扫描

## 九、扩展与集成

### 9.1 集成 Java 平台
在 `.env` 中配置：
```bash
JAVA_API_BASE_URL=http://your-java-platform:8080
JAVA_API_KEY=your-api-key
```

### 9.2 添加新的 LLM 模型
支持的模型：
- OpenAI (gpt-4o-mini, gpt-4, gpt-3.5-turbo)
- Claude (通过 OpenAI 兼容接口)
- DeepSeek
- Qwen

配置示例：
```bash
OPENAI_API_BASE=https://api.deepseek.com/v1
OPENAI_MODEL=deepseek-chat
```

### 9.3 启用联网检索
```bash
TAVILY_API_KEY=tvly-your-key
WEB_SEARCH_ENABLED=true
REALTIME_QUERY_ENABLED=true
```

## 十、常见问题

**Q: 如何查看 API 文档？**
A: 访问 http://localhost:8000/docs

**Q: 如何修改端口？**
A: 编辑 docker-compose.yml 中的 ports 配置

**Q: 如何清空数据重新开始？**
A: `docker-compose down -v && docker-compose up -d`

**Q: 如何升级服务？**
A: 拉取最新代码，重新构建：`docker-compose up -d --build`

**Q: 生产环境需要多少资源？**
A: 建议配置：
- CPU: 4 核心+
- 内存: 8GB+
- 磁盘: 50GB+ SSD
