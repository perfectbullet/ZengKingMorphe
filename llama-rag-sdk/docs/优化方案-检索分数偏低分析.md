## 问题背景

### 测试结果

```
查询: 什么是珐琅？
  [1] [score=0.5338] 珐琅——手工艺皇冠顶端的明珠,人类智慧的结晶。

珐琅工艺是在玻璃和细金属工艺的基础上由优秀的工匠发明出来,
又在手工艺发展的进程中不断地改良和丰富,最终成为我们今天所看到的样子。

珐琅是一门历史悠久...
  [2] [score=0.5266] 本书讨论的珐琅工艺是指"高温珐琅工艺",也有人称其为"大明火珐琅工艺"。制作方法为:将珐琅釉料施放在金属底板上,让金属底板和釉料共同经过700\~800摄氏度的高温烧制之后紧密结合成为一体。
```

### 问题分析

**分数偏低 (0.5338) 的原因**:

1. **文本风格不匹配**
   - 查询: 直接、简短的定义类问题 ("什么是珐琅?")
   - 文档: 文学性、隐喻性描述 ("皇冠顶端的明珠")
   - BGE-M3 更倾向于匹配语义相似的风格,而非事实定义

2. **文档分块问题**
   - 当前使用按标题分割 (heading-based chunking)
   - 定义文本可能被稀释在长段落中
   - 缺少独立的"定义块"

3. **Embedding 模型特性**
   - BGE-M3 擅长长文本语义理解
   - 对于简短的查询,可能需要调整策略

## 优化方案

### 方案 1: 改进文档分块策略 (定义提取)

**思路**: 在标题分割的基础上,进一步提取关键定义和核心概念

**实现示例**:
```python
def split_by_headings_with_definition_extraction(text: str, filename: str) -> list[tuple[str, str]]:
    """
    按标题分割 + 提取定义块
    优先提取 "是...是指..." 等定义句作为独立块
    """
    sections = split_by_headings(text, filename)

    enhanced_sections = []
    for heading, content in sections:
        # 提取定义句 (开头是 "xxx是..." 或 "xxx是指...")
        definition_match = re.search(r'(珐琅.*?是.{10,100}。)', content)

        if definition_match:
            # 添加独立的定义块
            enhanced_sections.append((f"{heading} - 定义", definition_match.group(1)))

        # 保留原完整内容块
        enhanced_sections.append((heading, content))

    return enhanced_sections
```

**优点**: 直接解决"定义"被稀释的问题
**缺点**: 可能产生重复内容,增加索引大小
**适用场景**: 教科书、技术文档等有明确定义的文档

### 方案 2: 查询重写/扩展

**思路**: 将"什么是珐琅?"重写为更明确的查询

**实现示例**:
```python
def rewrite_query(query: str) -> str:
    """查询重写策略"""
    if query.startswith("什么是") or query.startswith("What is"):
        entity = query.replace("什么是", "").replace("?", "").strip()
        return f"{entity}的定义和特点"
    return query

# 使用
query = rewrite_query("什么是珐琅?")
# -> "珐琅的定义和特点"
```

**优点**: 简单,不改变索引
**缺点**: 可能影响其他类型的查询
**适用场景**: 定义类、概念类问题

---

### 方案 3: 混合检索 + 重排序 ⭐ 强烈推荐

**思路**: 增加候选文档数量,使用重排序模型精炼结果

**实现示例**:
```python
# 1. 增加 top_k (从 3 到 10)
retriever = index.as_retriever(similarity_top_k=10)
results = retriever.retrieve(query)

# 2. 使用 BGE Reranker 精炼
from llama_index.postprocessor.cohere_rerank import CohereRerank

reranker = CohereRerank(
    model="BAAI/bge-reranker-v2-m3",
    top_n=3  # 最终返回 top 3
)

reranked_results = reranker.postprocess_nodes(results, query_str=query)
```

**优点**: 显著提升检索质量
**缺点**: 需要额外的 Reranker 模型服务
**适用场景**: 对检索质量要求高的场景
**参考服务**: BGE Reranker API (192.168.8.233:8091)

### 方案 4: 使用更强的 Embedding 模型

**思路**: 切换到针对问答优化的 embedding 模型

**模型对比**:
| 模型 | 特点 | 适用场景 |
|------|------|----------|
| BAAI/bge-m3 (当前) | 通用性强,支持多语言 | 通用检索 |
| BAAI/bge-large-zh-v1.5 | 中文问答优化 | **推荐** |
| moka-ai/m3e-large | 中文语义理解 | 中文文本 |

**实现示例**:
```python
embed_model = OpenAIEmbedding(
    model_name="BAAI/bge-large-zh-v1.5",  # 中文问答优化
    api_key="not-needed",
    api_base="http://192.168.8.233:8092/v1",
    embed_batch_size=32,
    timeout=300,
)
```

**优点**: bge-large-zh 在中文问答上表现更好
**缺点**: 模型更大,推理速度稍慢
**适用场景**: 中文问答系统

### 方案 5: 优化文档预处理 (元数据增强)

**思路**: 为每个文档添加摘要、类型等元数据

**实现示例**:
```python
documents.append(Document(
    text=cleaned,
    metadata={
        "source": md_file.name,
        "heading": heading,
        "type": "definition" if "是" in heading or "是指" in heading else "general",
        "length": len(cleaned),
        # 添加文档摘要
        "summary": content[:200]  # 前200字作为摘要
    }
))
```

**检索时使用元数据过滤**:
```python
retriever = index.as_retriever(
    similarity_top_k=3,
    filters={"type": "definition"}  # 优先匹配定义类文档
)
```

**优点**: 灵活的过滤策略
**缺点**: 需要预定义文档类型
**适用场景**: 结构化文档

---

### 方案 6: 文档内容增强 (类型前缀)

**思路**: 在 embedding 时为文档添加类型前缀

**实现示例**:
```python
# 为定义类文档添加前缀
if "是" in heading and ("定义" in heading or "指" in heading):
    enhanced_text = f"定义: {cleaned}"
else:
    enhanced_text = f"内容: {cleaned}"

documents.append(Document(text=enhanced_text, ...))
```

**优点**: 不改变模型,简单有效
**缺点**: 前缀需要精心设计
**适用场景**: 快速优化
